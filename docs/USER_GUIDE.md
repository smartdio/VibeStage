## 安装与启动

需要 Node.js 22.12 或更新的受支持版本、npm，以及支持 WebGL 的现代浏览器。导出 MP4 还需要系统可以执行 `ffmpeg`；无音频预览、PNG 和 PNG 序列导出不需要 FFmpeg；音频导入需要 FFmpeg 和 ffprobe。

从 GitHub 克隆或下载项目后，在仓库根目录运行：

```sh
git clone https://github.com/smartdio/VibeStage.git
cd VibeStage
npm ci
npm run dev
```

打开终端显示的本地地址，默认是 http://127.0.0.1:5173 。如果端口已被占用，以终端实际输出为准。开发服务需要保持运行；结束时在终端按 `Ctrl+C`。

macOS 使用 Homebrew 时，可以这样安装并确认 FFmpeg：

```sh
brew install ffmpeg
ffmpeg -version
```

本版本需要从源代码启动本地服务。`npm run build` 用于类型检查和前端打包验证，生成的 `dist/` 不包含完整的项目管理与导出服务，不能直接作为完整工作台部署到 GitHub Pages 等静态托管服务。

## 创建与编辑场景

首次打开且没有有效的上次选择时，默认进入“内置 · 运镜学习样板”。其中 32 个镜头各演示 12 秒，右侧显示用途、观察重点与练习提示。该项目固定置顶、只读，可观看和导出，不能修改或删除；点击“复制为我的项目”生成独立练习副本。详见 [样板说明](../examples/camera-school/README.md)。

也可以打开其他示例，或在界面中点击“新建场景”。也可以让 Agent 在仓库根目录执行：

```sh
npm run create-scene -- my-mv shot-01 blocking
```

这会创建 `projects/my-mv/scenes/shot-01.ts`，并在新项目中生成 `project.json`。同名场景已存在时会报错，不会覆盖。项目和场景目录名使用 1–48 位小写英文字母、数字、横线或下划线，首位为字母或数字；项目显示名称可以在 `project.json` 的 `name` 中设置为中文。

第三个参数是模板：`empty` 为基础空场景，`room` 为室内布景，`blocking` 为包含人物走位与多个机位的示例。省略时使用 `empty`。创建完成后，在工作台中选择对应项目和场景。

只有 `scenes/` 直属、符合上述命名规则的 `.ts` 文件作为场景入口。辅助函数放入项目的 `shared/` 等目录，项目专用模型放入 `assets/`，避免被当作独立场景加载。

## 让 Agent 接管

让具备本地代码编辑能力的 Agent 打开整个仓库，并先阅读 [AGENTS.md](../AGENTS.md) 与 [AGENT_GUIDE.md](../AGENT_GUIDE.md)。涉及模型导入时，再阅读 [MODEL_GUIDE.md](../MODEL_GUIDE.md)。可以直接向 Agent 提出这样的要求：

> 在 projects/my-mv 中新建 shot-01 场景，用两侧的方块建筑组成一条巷子。人物 A 在南侧慢走，人物 B 在北侧奔跑，增加一个从 A 肩后拍向 B 的机位。只修改这个项目，完成后检查预览并导出参考图。

Agent 创建或修改场景源文件，工作台检测到保存后重新加载。用户在预览中检查构图和动作，再继续通过对话调整。新增私人道具和模型构造函数应保存在 `user-models/`，具体项目的改动留在 `projects/<project>/`。

场景模块导出 `createScene()`，可以同步返回场景，也可以等待外部模型加载后异步返回。返回值包含原生 Three.js `scene`、机位映射 `cameras`、时长 `durationSeconds`、输出设置 `output`、逐帧求值函数 `update(timeSeconds)` 和资源释放函数 `dispose()`；`subjects` 可选，用于界面对象列表。完整实现可参考 [blocking 模板](../templates/blocking.ts) 和 [场景接口](../lib/core/types.ts)。

人物和道具通过 `position`、`rotation`、`scale` 及父子层级控制空间关系；关节旋转控制姿势；`update(t)` 控制走位、动作和摄影机运动。每次调用必须能独立计算指定时刻的完整状态，以便拖动时间轴、逐帧检查和导出。不要在场景内启动额外渲染循环，也不要用系统时间或未固定种子的随机数驱动拍摄状态。

场景统一使用米、秒和弧度，Y 轴向上；北为 −Z、南为 +Z、东为 +X、西为 −X。自由观察视图在地面边界外侧显示平铺的淡灰色方位标记，方便通过方向描述调整场景。

Agent 也可以通过已经打开的预览页面调用浏览器 API：

```js
window.vibeStage.getState();
await window.vibeStage.load('my-mv', 'shot-01');
window.vibeStage.seek(2.5);
window.vibeStage.camera('wide'); // 对应场景 cameras 中的键
await window.vibeStage.export('still'); // still | sequence | video
```

这些调用需要在工作台页面中执行，可使用 Agent 的浏览器工具。当前没有独立的无浏览器离线渲染命令。

## 基础模型与自己的模型库

`lib/core/` 提供方块、平面、球、圆柱、墙、桌、椅、简化车辆和关节人偶。内置人偶支持关节旋转、站姿、坐姿与行走循环；人物整体位移由场景代码单独控制。共享模型通过 `@vibestage/core` 导入，具体参数和骨架约定见 [Agent 使用说明](../AGENT_GUIDE.md)。

自定义 GLB 可以放在 `user-models/chair/model.glb`。glTF 模型需要连同 `.bin` 和纹理文件保留原有相对目录。场景中使用私有模型别名加载：

```ts
import {loadModel} from '@vibestage/core';
import chairUrl from '@vibestage/models/chair/model.glb?url';

// 放在异步 createScene() 内，stage 为已创建的白模场景。
const chair = await loadModel(chairUrl, {name: '我的椅子', scale: 1});
chair.root.position.set(1, 0, -1);
stage.scene.add(chair.root);
```

加载器默认将模型在 X/Z 方向居中，并把底部放到地面；`ground: false` 保留原始原点。通过 `scale` 转换单位，例如厘米模型使用 `0.01`。项目专用模型也可以使用 `../assets/model.glb?url` 相对导入，不要依赖本机绝对路径。

`user-models/` 也可以存放自定义 TypeScript 模型构造函数，供多个项目复用。导入动画、资源释放和 Draco / KTX2 / Meshopt 解码器配置见 [模型指南](../MODEL_GUIDE.md)。内置加载器支持 GLB/glTF，其他格式需要自行接入对应加载器或转换格式。

## 摄影机参数

每个透视机位可通过场景的 `cameraMetadata` 指定焦距、传感器尺寸、光圈、景别、运动说明和对焦目标或距离。焦距实际控制构图，输出画幅按传感器中心裁切；右侧面板同步显示镜头参数、有效画幅与视场角。点击“调节当前机位”可手动修改参数、位置与朝向，也可采用当前自由观察视角或新建机位。对焦目标可以绑定人物骨架节点，距离随人物移动更新。光圈与对焦实时控制景深，拍摄画面、HUD 操控、全屏、监看和 PNG／序列／视频导出共用同一渲染流程。减小 f 值会加强虚化；改变对焦距离会移动清晰平面。广角、小光圈和远距离对焦的虚化较轻，自由观察保持清晰以便布景。

自动切镜使用 `cameraCuts` 声明机位与起止时间，也可在“编辑分镜”中添加、删除片段，选择机位和调整切点。切镜时面板显示实际机位参数，展开“分镜计划”可跳到对应片段。旧场景不配置元信息也能继续使用原有 FOV。具体代码与参数约定见 [摄影机使用说明](../AGENT_GUIDE.md#摄影机参数与自动分镜)。

点击“操控机位”会暂停时间轴，并进入摄影机视角。按住鼠标或触摸拖动画面转向，点击画面后用 W/S 前后、A/D 左右、Q/E 升降，方向键微调朝向；滚轮调整移动速度。预览窗口内的摄影机 HUD 提供左右移动与转向控制盘、升降摇杆和速度选择；长按箭头持续操作，拖动盘心可控制方向，松手停止。点选焦距、光圈、对焦读数，在画面内打开档位、滑条与精确输入。“应用机位”把本次调整加入待保存修改，“取消”恢复进入前的机位与视图；应用后仍需点击“保存到项目”。

预览窗口和 HUD 都提供“全屏”入口，全屏保留机位操控、镜头参数和构图参考线；画面与参考线随窗口尺寸适配。点击“退出全屏”或按 Esc 返回工作台，不取消当前机位草稿。不支持浏览器原生全屏时使用占满浏览器窗口的模式。

HUD 的“构图”可选择三分法、黄金分割、中心十字、对角线，或关闭构图线；支持可选动作／字幕安全框、范围百分比、透明度和颜色。2.39:1、1.85:1、1:1、9:16 画幅参考仅用于预览遮罩，构图线跟随参考画幅，不改变输出尺寸。HUD、参考线与遮罩均不进入导出；偏好保存在本机浏览器。

手动修改先实时预览，点击“保存到项目”写入 `projects/<project>/settings/<scene>.camera.json`，刷新后保留；手动字段优先于场景代码，可恢复代码设置。未保存修改时暂不能导出或切换场景。

## 电影镜头预设

播放按钮两侧的“上一个镜头 / 下一个镜头”按机位列表顺序浏览，并将连续分镜展开为逐个片段。“下一个”进入分镜组首段，“上一个”进入末段，均定位到片段起点；组内逐段切换，走完后继续切换到相邻机位或分镜组。切换到独立机位时，定位到该机位在当前分镜组中的首次出现时间；当前组未引用时取其他组的首次引用，没有分镜引用时取预设开始时间或场景 0 秒。人物、道具、摄影机与对焦同时按目标时间更新。跳转进入拍摄画面并保留播放状态：播放中继续播放，暂停时停在目标帧。只有到达整个列表的首尾时，相应按钮才禁用。

右侧“电影镜头预设 → 从预设新建”，选择环境建立、双人、过肩、反应、细节、主观、推进、拉远、水平摇、上下摇、后跟、前跟、侧跟、短弧环绕、遮挡揭示或 A/B 拉焦；也可选择高低角度、顶拍、倾斜、升降、升起／下降、甩镜、平滑／快速变焦、滑动变焦、手持、完整环绕、主体固定、连续交接和穿行俯冲。绑定人物/物件与锚点，调整焦距、光圈、距离、高度、方位及时间节奏，应用后播放检查，再“保存到项目”。观看目标与对焦目标可单独设置。

已有预设的微调默认保留构图参考；重新取当前参考须勾选对应选项。运动机位通过预设参数调整；需要 HUD 自由操控时，“复制为固定机位”保留当前画面并新建独立机位。预设可加入连续分镜；全屏与导出使用相同采样，导出记录附带预设 ID、版本、配置与警告。

基础演示位于 [presets.ts](../examples/camera-lab/scenes/presets.ts)，第二、三批演示位于 [advanced.ts](../examples/camera-lab/scenes/advanced.ts)，包含俯视路径与 16 项进阶预设。首次初始化自动安装；已有私人项目不会被覆盖，可先用 `npm run create-scene -- camera-lab presets empty` 创建不存在的新场景，再把公共模板内容复制到新文件。预设不包含自动避障，仍需检查人物入画及路径穿墙。

## 独立分镜表演与跳切

同一场景可复用模型和布景，让前几镜连续表演，再切到人物和道具已重新摆位的镜头。“编辑分镜”中，每段可选择“延续上一段表演”或“独立表演 · 允许跳切”。独立段可选择场景提供的动作、动作起点，并在“人物与道具摆位”中调整起始位置、朝向和显示状态。

独立摆位保留动作后续位移与关节变化；后续“延续”段接着最近的独立动作和摆位执行。成片时间连续，表演时间可以跳跃；播放、任意跳转、循环和导出使用相同求值逻辑，音频继续按成片时间同步。单独选择实体机位仍查看原场景动作，选择分镜组才执行完整剪辑。

手动修改使用原有“保存到项目”，保存在私人 `.camera.json` 的分镜字段中。Agent 可以在场景的 `performances` 中编写任意动作，在 `updateCameras` 中按最终摆位跟拍；无需把复杂动作改写成固定 JSON。详见按需阅读的 [分镜表演指南](../agents/PERFORMANCES.md)，公共示例在 [montage 场景](../examples/montage/scenes/edit.ts)。

## 音频与分镜同步

在预览下方的时间轴点击“导入音频”，为当前场景添加一条已混好的参考音轨。支持 WAV、MP3、M4A、AAC、OGG、FLAC，单文件最大 64 MB、300 秒；导入时在本地转换为 48 kHz 双声道 WAV。需要已安装 FFmpeg（包含 ffprobe），不会上传到外部服务。

波形和分镜标记共用场景时间。点击波形可定位；选择连续分镜后，可在右侧“编辑分镜”调整切点。播放、暂停、逐帧移动、切换镜头和循环同步更新声音与画面；播放中跳镜头继续播放，暂停时停在目标帧。音轨以音频时钟驱动画面，渲染暂时变慢不会累计音画偏差。

“起始偏移”是第一份音频样本出现的场景时刻：`+1` 表示延后 1 秒，`-1` 表示跳过声音开头 1 秒。音量可调 0–200%，静音同时应用到预览与导出；调整后点击“保存音频设置”。音轨短于场景时尾部补静音，长于场景时按画面时长裁切，不自动改变场景时长。若需完整使用长音频，由 Agent 调整 `durationSeconds`、动作及分镜覆盖范围。

音频素材保存在 `projects/<project>/assets/audio/`，设置在 `projects/<project>/settings/<scene>.audio.json`，均留在本地私人项目中。重新加载后保留；移除或替换音轨不会删除原素材。导出 MP4 带声音；PNG 本身无声，图片序列 ZIP 附带原始 `soundtrack.wav` 与对齐设置，需按清单中的偏移使用。`manifest.json` 的 `audio` 记录素材、时长、偏移、音量和静音，`source.zip` 包含复现所需音频与设置。

首版面向单条已混好的声音；不含多轨剪辑、录音和自动节拍切镜。Agent 接口见 [音画同步指南](../agents/AUDIO.md)。

## 预览与导出

自由观察视角用于检查空间关系，拍摄机位用于检查实际画面。切换“拍摄画面”后可选择场景定义的机位。焦点不在输入框、按钮等控件时，空格播放或暂停，左右方向键逐帧移动。方位标记等编辑辅助元素不会出现在拍摄导出中。

代码保存后自动重载当前场景；加载失败时显示错误并清空旧画面。导出期间修改代码会延迟应用，完成后按界面提示重新加载，避免改变正在导出的表演。

导出支持单张 PNG、PNG 序列 ZIP 和 MP4，结果写入 `exports/<job-id>/`。单张图片导出当前时刻与所选机位；序列和视频按场景时长与帧率固定采样。例如 6 秒、24 fps 对应 144 帧。MP4 使用 FFmpeg 编码为 H.264、yuv420p；已导入音频时合成 AAC 音轨，偏移、音量和静音与预览一致。

每次导出附有 `manifest.json`、`cameras.json` 和 `source.zip`。摄影机记录包含逐帧镜头参数、对焦距离、世界位置与朝向，以及计划和实际分镜区间；PNG 序列 ZIP 内也包含此记录。源码快照包含当前项目、整个 `user-models/`、公共框架、构建配置和依赖锁文件，不包含其他用户项目。它用于私人备份与复现，分享前需要确认其中的模型库内容。内置教学项目例外：只打包公共源码，不包含私人项目和模型。还原时解压到空目录，运行 `npm ci` 和 `npm run dev`。

输出宽高需为 16–1920 之间的偶数，帧率为 1–60 fps，场景时长不超过 300 秒。序列和视频单次导出最多 1800 帧，源码快照最多 256 MB。首版默认使用 1280 × 720、24 fps；大尺寸序列压缩会占用较多内存。

取消任务后的部分文件会保留在对应目录。服务重启后，已导出文件仍在磁盘上，但界面的任务下载链接只在当前服务会话中有效。

## 公开框架与本地工作区

GitHub 仓库提供公共框架、基础模型库、模板与示例。`projects/` 保存用户自己的项目，`user-models/` 保存跨项目复用的私人模型。两个目录均由 `.gitignore` 排除，用户可以持续修改自己的场景，同时保留公共框架的目录结构。

```text
VibeStage/
├── src/                 # 工作台界面与预览运行时
├── server/              # 本地项目管理与导出服务
├── lib/core/            # 基础几何体、道具、关节人偶和模型加载器
├── templates/           # empty、room、blocking 场景模板
├── examples/            # 随仓库公开的示例项目
├── scripts/             # 初始化与创建场景命令
├── tests/               # 框架测试
├── projects/            # 本地用户项目，不提交 Git
│   └── my-mv/
│       ├── project.json # 项目显示名称等元数据
│       ├── scenes/      # 场景入口，例如 shot-01.ts
│       ├── shared/      # 可选：项目内共用的代码
│       └── assets/      # 可选：项目专用模型与纹理
├── user-models/         # 本地模型文件及可复用模型代码，不提交 Git
├── exports/             # 导出图片、视频和源码快照，不提交 Git
└── artifacts/           # 本地验证产物，不提交 Git
```

首次启动会创建缺失的本地目录；只有在 `projects/` 尚不存在时，才把 `examples/` 中的普通示例复制进去；`camera-school` 作为内置只读项目直接提供，不复制到私人目录。后续启动不覆盖用户修改，也不会重新创建已经删除的示例。公共示例的更新不会自动合并到本地副本。需要单独初始化时，执行 `npm run setup`。

Git 忽略只控制文件是否进入普通提交，不提供备份或加密。用户项目与模型需要自行备份；已经被 Git 跟踪的文件不会因新增忽略规则而自动取消跟踪。发布框架前应检查暂存内容，不要强制添加私人目录。

## 验证与常见问题

框架测试和构建只依赖公开示例；私人项目单独检查：

```sh
npm test
npm run build
npm run check:projects
```

项目没有出现在列表中时，检查目录和文件命名，以及入口是否位于 `projects/<project>/scenes/<scene>.ts`。首次使用前先运行 `npm run setup` 或 `npm run dev`，以生成本地目录和项目类型检查配置。

场景加载失败时，查看工作台错误提示与开发服务终端输出，再执行 `npm run check:projects` 定位类型问题。模型无法显示时，检查导入路径、单位比例和 glTF 的外部资源；压缩模型还需要配置相应解码器。

MP4 导出失败时，确认启动工作台的终端可以执行 `ffmpeg -version`。源码快照超限时，将暂不使用的模型移到工作台外的存储目录；每次导出都会打包整个私人模型库。

## 当前边界

此版面向拍摄参考，不提供手指骨架、IK、碰撞、脚底锁定、可视化关节编辑器或拖拽模型导入界面。复杂动作和模拟可以用场景代码扩展，但作者需要保证任意时间跳转时能正确复现状态。导入的人体骨架不会自动适配内置人偶动作。

景深采用薄透镜参数驱动的屏幕空间近似，光圈不改变曝光。透视机位配置有效焦距、传感器、光圈与前方对焦距离后自动启用；缺少参数、正交机位或无效焦平面保持清晰。模糊半径上限为画面高度的 3%，前景边缘、透明物体和被遮挡背景可能出现近似误差。构图线和 HUD 不参与景深，也不会进入导出。

本地服务默认只监听 `127.0.0.1`，不提供多人协作、账号系统或跨机器任务调度。场景代码可以运行 JavaScript，预览不属于第三方代码沙箱，只应运行可信代码。

选镜头与规划运镜可查阅 [电影镜头与运镜研究库](CAMERA_LIBRARY.md)，或读取 [32 项机器可读目录](camera-library.catalog.json)。三批共 32 项均已实现，可分别体验基础与进阶镜头实验室。Agent 的调用方法、参数及扩展约定见 [镜头预设指南](../agents/CAMERA_PRESETS.md)。

进一步编写场景参阅 [AGENT_GUIDE.md](../AGENT_GUIDE.md)，维护私人模型参阅 [MODEL_GUIDE.md](../MODEL_GUIDE.md)，Agent 的项目操作约定参阅 [AGENTS.md](../AGENTS.md)。

## 导演交付包

进入“交付信息”，填写项目共享影片说明、场景上下文，再选择镜头填写叙事、人物、动作节点、色彩与多光源。没有的内容主动选择“没有”，不要留空。动作节点时间相对当前镜头起点，角度和光源强度要写明参照系和单位。技术参数从实际画面自动记录，文字设计与白模实测分别保存。

可以随时保存草稿；完整性面板列出缺失和失效引用。修改分镜切点、机位或表演后，检查并确认复核。影片说明跨本项目场景共享，镜头资料独立保存。切换场景和导出前须保存或放弃未保存修改。

选择要交付的分镜组，点击“导出完整交付包”。delivery.zip 包含整片白模视频、影片说明和每镜头的生图说明／JSON、视频说明／JSON、关键帧 PNG、独立白模视频。若选择的是单个机位，则交付该机位完整时长。原 PNG、序列、参考视频入口继续支持资料未完成的旧项目。

完整包只保存在本地 exports。内含 source.zip 私人素材快照，请勿当作框架公开发布包。

### 镜头提示词

交付信息页的“生图与视频提示词”可分别生成中文预览。生图版用于该镜头首帧，视频版用于完整动作过程。点击采用后可直接编辑，使用页首“保存交付资料”保存。再次生成只更新预览，点击“采用预览，替换文本”才覆盖已有文字。

资料或画幅、帧率变化时会提示复核；实际摄影参数在导出时再次检查。可重新生成，或核对并修正文案后保留手改版本。完整包每镜头包含 image-prompt.txt、video-prompt.txt 和 prompts.json。旧项目没有提示词时，导出自动生成缺少的部分，不自动写回项目。整个过程在本地完成，不调用生图、视频或语言模型服务。


### 每镜头的摄影机与成像介质

在“交付信息”中选中镜头，展开“摄影机与成像介质”，填写机身、记录介质、画幅、镜头、滤镜、感光度、快门、白平衡、数字记录格式，以及胶片／胶卷型号、规格、冲洗扫描和颗粒晕光质感，点击“保存交付资料”。明确不使用的项目选择“没有”，未知项目保留“未填写”。旧项目可正常打开保存，但完整交付前需要补全这些项目。

这些资料描述最终画面设计，不表示白模已实现对应的胶片或机身效果。生图和视频提示词、两类镜头资料及交付包都会包含这些信息；修改后需要重新生成或复核已有提示词。

在“摄影机与成像介质”内，可分别选择“机身参考”“镜头参考”“胶片参考”预设。选择会立即填入对应文字；下方字段可直接修改，修改后选择器显示“自定义／尚未选择”。三类互不代选，其他镜头也不受影响。选择“没有指定”只声明该项没有指定，不会清空整份档案。胶片预设提供 EI 和冲洗风格起点，实际规格和扫描要求仍可自行补充。

更换预设后，已有生图／视频提示词会标记过期：分别生成预览、采用并保存；没有生成的提示词会在完整导出时自动生成。所有预设只影响文字资料，不修改白模的镜头参数、运动、胶片质感或输出尺寸。

白模视频与完整交付包中的参考视频、关键帧采用快速渲染：长边最高 640 像素，不应用景深、焦外模糊或阴影，保留原帧率与动作时间。单独 PNG／图片序列仍使用所选输出设置。交付资料的 output 保留最终影片目标尺寸，referenceOutput 记录实际参考文件尺寸；referenceRendering 明确参考画面省略的效果。摄影机记录中的焦距、焦点、光圈与景深配置仍用于设计与提示词，不表示白模参考已渲染这些效果。
